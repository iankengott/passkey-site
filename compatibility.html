Compatibility

Windows and Linux. Chrome and Firefox.

Testing so far uses software, virtual machines and lab pages, with a mock signer standing in for the key. A test of one setup does not prove every site or computer.

Works with

  • Windows 11 Pro and HomeLocal accounts: start-up, unlock, switch user, administrator prompt
  • Debian 13 GNOME and NixOS KDELogin screen, lock screen, sudo and polkit
  • Chrome and ChromiumPassword fill and passkey login
  • FirefoxPassword fill and passkeys on top-level pages
  • Ordinary password formsIncluding multi-step logins and frames, on lab pages and public demo sites

Does not work with

  • macOS, iPhone and iPadOutside the design: Windows and Linux only
  • Android and other phonesOutside the design
  • Sites that require a PIN or fingerprintThe key has neither, so it refuses
  • Disk unlock and start-up before the OSOutside version 1
  • Firefox passkeys inside embedded framesRefused by the prototype

Not tested yet: Microsoft account login, NixOS package install, everyday real sites at scale, a real, physical key.

Details by surface

Details by surface

Password filling

Chrome and Firefox fill a saved password after you approve, on Windows and Debian VMs and on lab pages. Multi-step logins, unusual field names and frames are covered.

Real everyday sites at scale are not tested yet. A site you saved that turns hostile can still read the password.

Evidence
  • R37 Repeatable · Synthetic page Destination checks refuse lookalike origins, subdomains, Punycode impostors, HTTP, other ports, stale documents, changed form actions and replaced frames
  • R41 Repeatable · Synthetic page Multi step logins, unfamiliar username field names and JavaScript forms
  • R109 Tested · Model Windows browser fills with the installed add-on: Chrome 156 and Firefox 160
  • R113 Tested · Model Debian setup from the .deb: install, enroll, both browsers
  • R118 Tested · Model Windows packaged Chrome approval with default ClearType
  • R119 Tested · Model Windows decoy refusal and b8 artifact investigation

Register of 13 November 2026. Software mocks and VMs; no hardware.

Passkey login

The key signs a one-time challenge where a site accepts a passkey with no PIN. On Windows this goes through the Windows passkey plugin.

Sites that require a PIN or fingerprint are refused. Firefox passkeys inside embedded frames are refused by the prototype.

Evidence
  • R10 Repeatable · Model Windows passkey plugin accepts a provider that returns approval with no PIN
  • R43 Repeatable · Synthetic page T2 create and get on Microsoft Passkey Playground and Duo WebAuthn.io with verification unset
  • R49 Repeatable · Synthetic page Passkey create and get from frames with page replacement and a visible top origin
  • R80 Tested · Model A caller that requires user verification rejects the plugin response without it
  • R93 Tested · Model Windows Home passkey plugin repeats: ten approvals plus a clean reboot repeat

Register of 13 November 2026. Software mocks and VMs; no hardware.

Windows local accounts

Windows 11 Pro and Home: start-up login, unlock, switch user and the administrator prompt, with an installer and uninstaller. Text scaling at 175 and 200 percent and Narrator were checked.

No Microsoft account login. Update coverage is partial. One unexplained Windows verification flag remains a stated limit.

  • R108 Tested · Model Windows setup: install, enroll and uninstall from the built ZIP

Linux login

Debian 13 with GNOME and NixOS with KDE: login screen, console, sudo, lock screen and polkit. Debian has a .deb installer.

The NixOS package is not tested in a VM. GNOME Keyring stays locked after a key login. At 1280 × 800, KDE clips part of the lock screen.

Evidence

  • R100 Tested · Model Debian lane D: console login and sudo with the N13 approval prompt
  • R101 Tested · Model Debian GDM login screen with the N13 approval prompt and password fallback
  • R105 Tested · Model Debian GNOME Keyring after a key login
  • R113 Tested · Model Debian setup from the .deb: install, enroll, both browsers
  • R116 Not tested · Document NixOS package in a VM
  • R122 Tested · Model KDE N13 lock prompt geometry at stock and fixture 1080p
  • R123 Tested · Model KDE lock approval, no-release, recovery and native controls with D28 fixture layout

Register of 13 November 2026. Software mocks and VMs; no hardware.

Outside version 1

No disk unlock or typing before the OS starts. macOS, iPhone, iPad and Android are outside the design.

Refused on purpose

A site that requires a PIN or fingerprint gets a refusal. So does a Firefox passkey request inside an embedded frame.

Not shown yet

No physical key, certification, extraction resistance or wide real-site acceptance. A survey of 20 popular sites found none that documents this exact passkey type.
